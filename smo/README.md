`ИБ | ИЗ1 | ПЗ2 | Д1ОЗ3 | Д1ОО3 | Д2П1 | Д2Б2 | ОР1 | ОД1`

| Код | Правило | Где в коде |
| --- | --- | --- |
| ИБ | Источник бесконечный: число событий не зависит от состояния системы | `Camera`, `Simulation` |
| ИЗ1 | Пуассоновский поток: интервалы между событиями экспоненциальные | `Camera.schedule_next` |
| ПЗ2 | Время анализа распределено равномерно на `[service_min, service_max]` | `AnalyticsModule.start` |
| Д1ОЗ3 | Постановка в первую свободную ячейку с начала буфера, остальные не сдвигаются | `Buffer.first_free_slot`, `AdmissionDispatcher.accept` |
| Д1ОО3 | При полном буфере отказ получает самая старая заявка, новая занимает её ячейку | `Buffer.oldest_slot`, `AdmissionDispatcher.accept` |
| Д2П1 | Прибор: первый свободный, поиск всегда с прибора № 1 | `ModulePool.first_free` |
| Д2Б2 | Из буфера берётся самая поздняя заявка (LIFO) | `Buffer.newest_slot`, `SelectionDispatcher` |
| ОР1 | Автоматический режим: сводная таблица результатов | `SummaryView` |
| ОД1 | Пошаговый режим: календарь событий, буфер, приборы, статистика | `StepView` |


- Очередь не сдвигается, поэтому «самая старая» и «самая поздняя» заявки определяются по времени поступления `arrived_at`, а не по номеру ячейки.
- Приборы не отказывают, они бывают заняты. Отказ возможен только в буфере: вытесняется самая старая заявка.
- Диспетчер постановки работает только с буфером и ничего не знает о приборах. Если прибор свободен, буфер пуст, поэтому заявка проходит через буфер с нулевым ожиданием.

## Запуск

```bash
# автоматический режим: сводная таблица (ОР1)
python main.py auto --seed 1

# пошаговый режим: Enter - шаг, a - до конца, q - выход (ОД1)
python main.py step --seed 3 --requests 12 --buffer 2 --modules 1 --rate 8
```

Параметры (все необязательные):

| Параметр | Значение по умолчанию | Смысл |
| --- | --- | --- |
| `--cameras` | 3 | число истчников (камер) |
| `--rate` | 5.0 | интенсивность потока одной камеры, событий в секунду |
| `--modules` | 2 | число приборов |
| `--buffer` | 5 | число ячеек буфера |
| `--service-min` | 0.02 | нижняя граница времени анализа, секунды |
| `--service-max` | 0.20 | верхняя граница времени анализа, секунды |
| `--requests` | 1000 | сколько заявок сформировать за прогон |
| `--seed` | не задан | зерно генератора, одинаковое зерно даёт одинаковый результат |

## Что показывают режимы

**Пошаговый режим** на каждом шаге выводит события шага (заявка сформирована, поставлена в буфер, выбита из буфера, выбрана из буфера, отправлена на прибор, обработана), календарь событий таблицей, состояние источников (сколько сформировано, отказов, когда придёт следующая заявка), ячейки буфера, состояние приборов и накопленную статистику с процентом отказа.

**Автоматический режим** выводит сводную таблицу: сформировано и обработано заявок, число и вероятность отказов, среднее время ожидания, обслуживания и пребывания, дисперсии времени ожидания и обслуживания, показатели по каждой камере и загрузку приборов.

Как считаются показатели:

- ожидание = начало анализа − постановка в буфер;
- пребывание = конец анализа − поступление;
- вероятность отказа = число отказов / число сформированных заявок;
- загрузка прибора = суммарное время анализа на приборе / длительность моделирования;
- времена и дисперсии считаются по обработанным заявкам, отказанные заявки в них не входят.

## Триггеры диспетчеров

| Триггер | Что запускается |
| --- | --- |
| Наступило время обнаружения | Камера формирует событие, диспетчер постановки ставит его в буфер |
| Событие поставлено в буфер | Диспетчер выбора ищет свободный прибор |
| Наступило окончание анализа | Прибор освобождается, статистика учитывает заявку |
| Прибор освободился | Диспетчер выбора берёт следующую заявку из буфера |



## Соответствие диаграмме классов

Имена методов в коде записаны в стиле Python (`snake_case`), в диаграмме — `camelCase`.

| Диаграмма | Код |
| --- | --- |
| `Simulation.runStep`, `runAuto` | `smo/simulation.py`: `run_step`, `run_auto` |
| `Camera.generateEvent`, `scheduleNext` | `smo/source.py`: `generate_event`, `schedule_next` |
| `DetectionEvent`, `Event` | `smo/models.py` |
| `EventCalendar.schedule`, `next`, `upcoming`, `now` | `smo/event_calendar.py` |
| `Buffer.firstFreeSlot`, `oldestSlot`, `newestSlot`, `put`, `remove`, `isEmpty`, `snapshot` | `smo/buffer.py`: `first_free_slot`, `oldest_slot`, `newest_slot`, `put`, `remove`, `is_empty`, `snapshot` |
| `AdmissionDispatcher.accept`, `SelectionDispatcher.onEventQueued`, `onModuleFreed` | `smo/dispatchers.py`: `accept`, `on_event_queued`, `on_module_freed` |
| `ModulePool.firstFree`, `get`, `busyTimes`; `AnalyticsModule.start`, `finish` | `smo/modules.py` |
| `Statistics`, `Summary` | `smo/stats.py` |
| `StepView`, `SummaryView` | `smo/views.py` |

Поля классов приватные (префикс `_`), данные читаются через свойства и методы.

## Структура проекта

```
smo/
  main.py                запуск и разбор параметров
  models.py            заявка, событие календаря, перечисления
  event_calendar.py    календарь событий
  buffer.py            буфер (Д1ОЗ3, Д1ОО3, Д2Б2)
  modules.py           приборы и пул (ПЗ2, Д2П1)
  source.py            камера (ИБ, ИЗ1)
  dispatchers.py       диспетчеры постановки и выбора
  stats.py             статистика и сводка
  views.py             вывод ОД1 и ОР1
  simulation.py        параметры и управляющий цикл
```
